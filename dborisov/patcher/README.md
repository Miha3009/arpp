# Patcher (описание сгенерировано)

Библиотека для эффективного хранения и загрузки патчей из сеточных геофизических данных с использованием сжатия ZSTD.

## Установка

Нужно иметь C++17, torch и zstd, для WINDOWS пока не адаптировано, но должно быть несложно

```bash
./build.sh
```

### macOS (Apple Silicon)

На Apple Silicon `setup.py` сам не прописывает пути к Homebrew-zstd и собирает
universal2, поэтому нужны переменные окружения. Полный рабочий рецепт:

```bash
# build-зависимости в venv (torch уже должен стоять)
pip install pybind11 "setuptools>=61.0"

export CPLUS_INCLUDE_PATH="$(brew --prefix zstd)/include:$CPLUS_INCLUDE_PATH"
export LIBRARY_PATH="$(brew --prefix zstd)/lib:$LIBRARY_PATH"
export ARCHFLAGS="-arch arm64"            # zstd из Homebrew только arm64, не universal2
export MACOSX_DEPLOYMENT_TARGET=11.0       # нужно для std::filesystem (требует macOS 10.15+)

./build.sh
```

Зачем каждая переменная:
- `CPLUS_INCLUDE_PATH` / `LIBRARY_PATH` — clang по умолчанию не ищет в `/opt/homebrew`,
  без них `fatal error: 'zstd.h' file not found`.
- `ARCHFLAGS="-arch arm64"` — иначе сборка идёт universal2 (arm64+x86_64), а Homebrew-zstd
  только arm64, и линковка x86_64-среза падает.
- `MACOSX_DEPLOYMENT_TARGET=11.0` — Python-фреймворк по умолчанию таргетит macOS 10.9,
  где нет `std::filesystem` (`'path' is unavailable: introduced in macOS 10.15`).

**Важно при использовании:** импортируйте `torch` ДО `patcher`, иначе
`Library not loaded: @rpath/libtorch.dylib` (в `.so` не зашит rpath на libtorch):

```python
import torch
import patcher
```

**ABI:** расширение собрано против конкретной версии torch. После апгрейда/даунгрейда
torch модуль нужно пересобрать (`./build.sh`).

## Запрос (Request)

Параметры запроса:

| Параметр | Тип | Описание |
|----------|-----|----------|
| `element` | str | Имя переменной (например `"t2m"`, `"tp"`) |
| `x0`, `y0` | int | Начальные координаты в пикселях |
| `t0` | str | Начальная дата в формате `YYYYMMDD` |
| `xSize`, `ySize`, `tSize` | int | Размеры запрашиваемого блока |
| `xyStep`, `tStep` | int | Шаги дискретизации (1 = без прореживания) |
| `tag` | int | Метка для разделения прогнозов (по умолчанию 0) |

Сетка для ERA5 - 0.25, для прогнозов 1 градус. Разрешение по времени - 1 сутки.

```python
req = patcher.Request("t2m", 100, 50, "20240101", 32, 32, 10, 1, 1)
```

## Ответ

Функция `patcher.load(context, [reqs])` возвращает **список тензоров PyTorch** — по одному на каждый запрос.

### Размерности тензора

- **3D**: `[T, H, W]` — если данные одномерные (время, высота, ширина)
- **4D**: `[E, T, H, W]` — если данные ансамблевые (ансамбль, время, высота, ширина)

### Особенности

- **Возвращает аномалии**. Для получение климата (1991-2020) нужно использовать `patcher.load_climate(context, [reqs])` с
  аналогичным интерфейсом
- **Цикличность по долготе (X)** — при выходе за правый край данные продолжаются с левого края
- **Экстраполяция по широте (Y)** — при выходе за верхнюю или нижнюю границу повторяется последняя доступная строка
- **Tag** — используется для разделения прогнозов с разными датами старта (в данном случае tag=месяц старта). Прогнозы с разными `tag` не смешиваются при агрегации
- **NAN** должно возникать только, если за указанную дату (хотя бы за одну дату при осреднении по датам) нет данных
